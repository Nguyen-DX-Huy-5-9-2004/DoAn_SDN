1. Tấn công cạn kiệt CPU: "Thuật toán Băm Mật khẩu" (Hash Exhaustion)
Kịch bản: Khi người dùng đăng nhập hoặc đăng ký, mật khẩu phải được băm (hash) bằng các thuật toán mạnh như bcrypt, PBKDF2 hoặc Argon2 để bảo mật. Quá trình này được thiết kế cố tình chạy rất chậm và ngốn CPU.
Cách Hacker làm: Kẻ tấn công tạo ra hàng chục nghìn request gửi mật khẩu dài ngoằng (ví dụ 10.000 ký tự) vào endpoint /api/login.
Hậu quả trên web1: Database chưa kịp làm gì thì CPU của web1 đã giật lên 100% để tính toán mã băm cho các mật khẩu giả mạo này. Toàn bộ web sẽ đơ cứng.
Triển khai trong Django: Rất dễ. Chỉ cần tạo một API nhận một chuỗi text và chạy hàm make_password() của Django trên chuỗi đó.

2. Tấn công cạn kiệt RAM & I/O: "Xử lý ảnh / Render PDF" (Resource Heavy Tasks)
Kịch bản: Trang web có tính năng cho phép người dùng tải lên avatar để cắt xén (crop/resize), hoặc tính năng bấm vào nút "Tải xuống báo cáo PDF/Excel".
Cách Hacker làm: Gửi liên tục các request yêu cầu server render một file PDF phức tạp, hoặc gửi một bức ảnh "bom pixel" (kích thước file rất nhỏ nhưng khi bung ra bộ nhớ để xử lý thì rộng hàng chục nghìn pixel).
Hậu quả trên web1: Thư viện xử lý ảnh (Pillow) hoặc render PDF (ReportLab) sẽ ngốn sạch hàng trăm MB RAM cho mỗi request. Chỉ cần vài chục request song song, web1 sẽ bị báo lỗi "Out of Memory" (OOM) và tự sập.

3. Tấn công cạn kiệt Worker: "Kẻ câu giờ" (External API Timeout / Sleep)
Kịch bản: Web của bạn cần gọi sang một dịch vụ bên thứ 3 (ví dụ: gọi API ngân hàng để kiểm tra thanh toán, hoặc gọi API thời tiết).

Cách Hacker làm: Bắn request vào API đó.

Đánh lừa hệ thống: Thay vì đánh sập CPU hay RAM, bạn cấu hình cho API này cố tình bị sleep(5) hoặc kết nối đến một server không tồn tại với timeout dài. Gunicorn/Django thường chỉ có khoảng 4-8 "công nhân" (workers) để phục vụ khách. Khi 8 công nhân này đều đang đứng chờ cái lệnh sleep(5) kia, khách hàng thứ 9 truy cập web sẽ bị từ chối phục vụ ngay lập tức. CPU vẫn 0%, RAM vẫn trống, nhưng web lại chết! Đây là một dạng đánh lừa hệ thống giám sát cực kỳ kinh điển.

4. Tấn công giải mã dữ liệu: "Bơm JSON khổng lồ" (JSON Parsing Exhaustion)
Kịch bản: Ứng dụng nhận dữ liệu từ client dưới dạng JSON (ví dụ lưu thông tin giỏ hàng).

Cách Hacker làm: Gửi một cục JSON được lồng ghép (nested) cực kỳ sâu, hoặc chứa một mảng (array) dài hàng triệu phần tử.

Hậu quả trên web1: Khi Django gọi json.loads(), nó phải đọc toàn bộ cục dữ liệu đó và chuyển đổi thành cấu trúc Dictionary của Python trên RAM. Quá trình này sẽ khóa chặt CPU và làm đầy RAM siêu nhanh.

Sự thú vị khi đưa vào đồ án:
Nếu bạn làm đủ các kịch bản này, Dashboard của bạn sẽ hiển thị các triệu chứng cực kỳ đẹp mắt và khác biệt:

Đánh Hash -> CPU vọt lên nóc, RAM bình thường.

Đánh Image/PDF -> RAM đầy vọt, CPU tăng vừa.

Đánh Timeout -> Số lượng Connection tăng vọt, CPU/RAM chả có hiện tượng gì.
